# Архитектура TravelBroke

## Слои

| Слой | Модуль | Ответственность | Что НЕ делает |
|---|---|---|---|
| HTTP | `travelbroke.api` | Валидация запроса, сериализация ответа | Не ходит в MCP, не считает маршруты |
| Домен | `travelbroke.reach` | Веер запросов, подбор стыковок через хабы | Не знает про HTTP и про формат ответов MCP |
| Интеграция | `tutukit` | Всё общение с MCP Туту, кэш, сжатие, диагностика | Не знает про города-кандидаты и бюджеты |
| Клиент | `web/` | Карта, ползунки, перекраска, карточка маршрута | Не считает маршруты, только раскрашивает матрицу |

Правило: зависимости идут строго вниз. `tutukit` не импортирует `travelbroke`,
домен не импортирует `fastapi`.

## Поток данных

```
Пользователь двигает ползунки
        │
        ├─ первый расчёт ──> POST /api/reachable
        │                      └─> reach.fan_out()       до 380 городов, 8 потоков
        │                            └─> tutukit.client   search_multitransport
        │                                  ├─> cache      промах → сеть, попадание → диск
        │                                  └─> compact    160 КБ → ~1 КБ
        │                      └─> reach.deepen()        проверка стыковок через хабы
        │                      <── матрица городов целиком
        │
        └─ последующие движения ползунка ──> пересчёт на клиенте, без сети
```

Ключевое архитектурное решение: **сервер отдаёт матрицу целиком, а не отвечает
на каждое движение ползунка**. Это снимает нагрузку с MCP (в который в день
хакатона бьёт 71 команда) и делает интерфейс мгновенным.

## Составные маршруты

- **Узлы** — города (гео-id Туту).
- **Рёбра** — конкретные рейсы: цена, время отправления и прибытия, вид
  транспорта, станция отправления и прибытия.
- **Валидация стыковки** — связка годится, только если между прибытием и
  отправлением остаётся запас: 60 минут базово, +90 при наличии самолёта, +60
  при смене вокзала. Названия станций MCP отдаёт настоящие, так что разные
  вокзалы мы видим; когда названий нет, считаем их разными и добавляем запас.
  Верхняя граница ожидания — 20 часов. Обоснование — в ADR-0004.
- **Второе плечо ищется и на следующий день** — ночная пересадка для дальнего
  направления нормальна, а несуществующая стыковка — нет.
- **Ограничения** — не более трёх пересадок и ограниченный набор городов-хабов.
  Иначе комбинаторика не окупается за отведённое время.

## Кэш и устойчивость

`tutukit.cache` пишет ответы MCP на диск и умеет режим реплея. Это даёт:

- дешёвые повторные прогоны во время разработки;
- работающее демо, если `mcp.tutu.ru` недоступен;
- воспроизводимость: один и тот же прогон даёт один и тот же результат.

Таймаут на вызов — от 15 секунд: в разведке видели ответ на 13,2 секунды.

## Известные ограничения

MCP Туту не отдаёт статусы и задержки рейсов, погоду, POI и историю покупок.
Поэтому TravelBroke считает **структурную** досягаемость и структурный риск
пересадки, а не предсказывает опоздания. Это осознанное ограничение, а не баг:
там, где данных нет, интерфейс говорит об этом прямо.

## Как слои удерживаются

Разделение выше — не соглашение на словах. `tests/test_architecture.py`
разбирает исходники через `ast` и падает в CI, если:

- `tutukit` импортировал `travelbroke` (обвязка перестала быть переиспользуемой);
- доменный модуль импортировал `fastapi`/`starlette`/`uvicorn`/`pydantic`
  (расчёт перестал запускаться без веб-приложения);
- `networkx` просочился в `api.py` (логика сползла в контроллер);
- у модуля или публичного объекта пропал docstring.

Правило, которое нельзя нарушить молча, остаётся правдой дольше, чем правило,
записанное только в документе.

## Обработка ошибок

Отказ MCP не должен выглядеть как пустая карта — пользователь не отличит
«ничего не нашлось» от «сервис лёг». Поэтому у каждого уровня свой ответ:

| Что отказало | Кто ловит | Что видит пользователь |
|---|---|---|
| Сеть до `mcp.tutu.ru` | `tutukit.client` | Кэш отвечает прошлым ответом; в режиме `replay` демо работает целиком с диска |
| Пустая выдача поиска | `tutukit.diagnose` | Причина словами: дата прошла, продажи не открыты, фильтры строгие или рейсов нет |
| Цена не пришла | `reach` + клиент | «Цена неизвестна» вместо нуля; такой рейс не участвует в сравнении цен |
| Город не зарезолвился | `travelbroke.cities` | Направление отбрасывается: цену Петербурга нельзя показать в точке Le Lamentin |
| Векторная подложка не поднялась | `web/src/App.tsx` | Молчаливый откат на растровые тайлы, карта остаётся рабочей |
| `create_checkout_link` не дал ссылку | `api.checkout` | Честный отказ; общую страницу поиска вместо конкретного рейса не открываем |

Общее правило: там, где данных нет, интерфейс говорит об этом прямо, а не
подставляет правдоподобное значение.

## Стратегия тестирования

| Уровень | Чем покрыт | Почему так |
|---|---|---|
| Разбор ответов MCP | `tests/test_compat.py`, `test_compact.py` | Схемы Туту расходятся с документацией — расхождения зафиксированы тестами |
| Диагностика пустых ответов | `tests/test_diagnose.py` | Четыре причины, которые сервер отдаёт неотличимо |
| Кэш и реплей | `tests/test_cache.py` | От него зависит устойчивость демо |
| Доменные расчёты | `tests/test_reach.py` | Стыковки, квоты пула, честность цен |
| HTTP-контракт | `tests/test_api.py` | Схема ответа, коды ошибок |
| Границы слоёв | `tests/test_architecture.py` | См. выше |
| Логика клиента | `web/src/*.test.ts` (vitest) | Выбор оффера, разбор ссылки, монотонность рампы |

Сеть в тестах не участвует: ответы MCP берутся из фикстур и кэша, поэтому
прогон детерминирован и не зависит от доступности Туту.

## Точки расширения

- **Новый вид транспорта.** Добавить в `MODES` и в `tutukit.compat`, где живут
  различия схем поиска. Домен и клиент подхватят его через `by_mode`.
- **Новый источник предложений.** Реализовать интерфейс вызова в `tutukit`;
  `travelbroke.reach` не знает, кто отвечает на `search_multitransport`.
- **Другая стратегия отбора направлений.** `cities.destinations()` — единственное
  место, где решается, какие города попадут в веер.
- **Отели и места.** `tutukit` уже умеет `search_hotels` и `get_rail_seatmap`;
  в продуктовый сценарий они пока не выведены — это осознанный объём, а не
  недостающая интеграция.

## Компромиссы, принятые осознанно

| Решение | Что выиграли | Чем заплатили |
|---|---|---|
| Матрица целиком на клиент | Мгновенные фильтры, ноль запросов на движение ползунка | Ответ тяжелее; фильтры ограничены тем, что уже посчитано |
| Пул до 380 направлений | Расчёт укладывается в разумное время | Не весь каталог из 3 393 городов проверяется в одном поиске |
| Квоты по континентам | Дальние направления не вытесняются соседними странами | Пул зависит от классификации стран, а не только от расстояния |
| Кэш с длинным TTL | Демо переживает недоступность MCP | Цены могут отставать от живых на время TTL |
| Свои контролы вместо системных | Единый вид в обеих темах и на Windows | Больше кода, чем у нативных `select` и `input[type=date]` |
