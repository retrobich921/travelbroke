# Архитектура TravelBroke

## Слои

| Слой | Модуль | Ответственность | Что НЕ делает |
|---|---|---|---|
| HTTP | `travelbroke.api` | Валидация запроса, сериализация ответа | Не ходит в MCP, не считает маршруты |
| Домен | `travelbroke.reach` | Веер запросов, построение графа, поиск путей | Не знает про HTTP и про формат ответов MCP |
| Интеграция | `tutukit` | Всё общение с MCP Туту, кэш, сжатие, диагностика | Не знает про города-кандидаты и бюджеты |
| Клиент | `web/` | Карта, ползунки, перекраска, карточка маршрута | Не считает маршруты, только раскрашивает матрицу |

Правило: зависимости идут строго вниз. `tutukit` не импортирует `travelbroke`,
домен не импортирует `fastapi`.

## Поток данных

```
Пользователь двигает ползунки
        │
        ├─ первый расчёт ──> POST /api/reachable
        │                      └─> reach.fan_out()       40–60 городов, 8 потоков
        │                            └─> tutukit.client   search_multitransport
        │                                  ├─> cache      промах → сеть, попадание → диск
        │                                  └─> compact    160 КБ → ~1 КБ
        │                      └─> reach.build_graph()   networkx
        │                            └─> Дейкстра + Yen  k=3 маршрута на город
        │                      <── матрица городов целиком
        │
        └─ последующие движения ползунка ──> пересчёт на клиенте, без сети
```

Ключевое архитектурное решение: **сервер отдаёт матрицу целиком, а не отвечает
на каждое движение ползунка**. Это снимает нагрузку с MCP (в который в день
хакатона бьёт 71 команда) и делает интерфейс мгновенным.

## Граф маршрутов

- **Узлы** — города (гео-id Туту).
- **Рёбра** — конкретные рейсы: цена, время отправления и прибытия, вид
  транспорта, станция отправления и прибытия.
- **Вес** — цена плюс штраф за пересадку плюс штраф за час в пути. Коэффициенты
  вынесены в настройки: ползунки пользователя меняют не граф, а фильтр по нему.
- **Валидация стыковки** — ребро годится, только если между прибытием и
  отправлением есть буфер: 60 минут на одном вокзале, 120 на разных. Названия
  станций MCP отдаёт настоящие, так что разные вокзалы мы видим.
- **Ограничения** — не более двух пересадок, не более десяти городов-хабов.
  Иначе комбинаторика не окупается за отведённое время.

## Кэш и устойчивость

`tutukit.cache` пишет ответы MCP на диск и умеет режим реплея. Это даёт:

- дешёвые повторные прогоны во время разработки;
- работающее демо, если `mcp.tutu.ru` недоступен;
- воспроизводимость: один и тот же прогон даёт один и тот же результат.

Таймаут на вызов — от 15 секунд: в разведке видели ответ на 13,2 секунды.

## Известные ограничения

MCP Туту не отдаёт статусы и задержки рейсов, погоду, POI и историю покупок.
Поэтому TravelBroke считает **структурную** досягаемость и структурный риск
пересадки, а не предсказывает опоздания. Это осознанное ограничение, а не баг:
там, где данных нет, интерфейс говорит об этом прямо.
