# ADR-0003. Дисковый кэш как основа стабильности

**Статус:** принято, 2026-08-19

## Контекст

Карта делает широкий веер обращений к внешнему MCP Туту. На холодном кэше
скорость расчёта зависит от сети, доступности MCP и числа проверяемых
направлений; заранее обещать фиксированное время выполнения было бы нечестно.

## Решение

Все ответы MCP пишет `tutukit.cache` на диск.

1. TTL по умолчанию — неделя (`TB_CACHE_TTL_S`), чтобы повторный просмотр не
   требовал заново опрашивать внешний сервис.
2. `python -m travelbroke.warm` может заранее прогреть выбранные сценарии.
3. `TB_CACHE_MODE=replay` отключает сеть и воспроизводит только записанные
   ответы — аварийный режим для демонстрации при недоступности MCP.

Прогресс-бар не симулирует проценты: он показывает разницу фактического
счётчика вызовов до и во время текущего запуска.

## Последствия

**Хорошее.** Повторные проверки быстры, расходы на разработку ниже, а сценарий
демо можно воспроизвести без сети.

**Плохое.** Кэшированная цена может устареть. Карточка поэтому предупреждает,
что окончательные цену и наличие надо подтвердить на Туту.

## Альтернативы

- Только live-запросы: максимальная свежесть, но хрупкое демо.
- Кэш в памяти: не переживает перезапуск процесса.
