# ADR-0002. Матрица цен уходит на клиент целиком

**Статус:** принято, 2026-08-19

## Контекст

Основное взаимодействие в TravelBroke — движение ползунка бюджета. Если каждое
такое движение уходит запросом на сервер, а оттуда в MCP Туту, интерфейс
превращается в ожидание: одиночный вызов занимает от 0,2 до 13 секунд.

В день хакатона в `mcp.tutu.ru` бьёт 71 команда одновременно. Генерировать
десятки запросов на одно перетаскивание ползунка — плохо и для отзывчивости,
и для чужого сервера.

## Решение

`POST /api/reachable` возвращает результат по **всем** городам-кандидатам сразу,
включая минимальную цену и минимальное время по каждому виду транспорта
(`meta.modes_summary` из ответа Туту).

Ползунки бюджета и времени, а также тумблеры видов транспорта фильтруют и
перекрашивают эту матрицу **на клиенте**. Ни одно из этих действий не порождает
сетевого запроса.

К серверу приложение обращается только при смене города отправления, даты или
режима поиска пересадок — то есть когда действительно нужны новые данные.

## Последствия

**Хорошее.** Карта реагирует мгновенно, в пределах одного кадра. Нагрузка на MCP
падает на порядок. Демонстрация не зависит от сетевых задержек в момент показа.

**Плохое.** Ответ тяжелее, чем при постраничной выдаче: примерно 60–70 городов
с разбивкой по видам транспорта. На практике это десятки килобайт после сжатия —
приемлемо, тем более что `tutukit.compact` заранее выбрасывает всё лишнее из
ответов Туту (поиск авиа отдаёт до 160 КБ на один запрос).

**Риск.** Значения по видам транспорта берутся из сводки Туту, а не из полного
перебора вариантов. Когда пользователь выключает часть видов транспорта, цена
может отличаться от той, что даст новый поиск с этим набором. Это осознанный
размен точности на отзывчивость, и он ограничен: карточка конкретного города
всегда показывает реальные найденные сегменты.

## Альтернативы

- **Запрос на каждое изменение фильтра.** Точнее, но интерфейс становится
  неотзывчивым, а нагрузка на общий MCP — неприличной.
- **Дебаунс запросов.** Смягчает проблему, но не решает: задержка в секунду
  всё равно ломает ощущение живой карты.
