# ADR-0002. Матрица результатов фильтруется в браузере

**Статус:** принято, 2026-08-19

## Контекст

Главное действие в TravelBroke — менять бюджет, время и транспорт, сравнивая
карту. Если каждый щелчок запускает новый веер запросов в MCP Туту, интерфейс
не отвечает, а внешняя интеграция получает лишнюю нагрузку.

## Решение

`POST /api/reachable` один раз возвращает матрицу кандидатов: реальные офферы,
минимальные цены/время по транспорту, составные маршруты и причины пустого
результата. Браузер локально применяет к этой матрице:

- бюджет и лимит времени;
- выбранные виды транспорта;
- окно отправления и прибытия.

Смена города, даты, пассажиров, набора транспорта, режима «только за границу»
или обратного билета меняет сами данные и требует явной кнопки «Обновить
карту». На стартовом экране любой выбор является только настройкой: поиск
запускает одна кнопка «Показать карту».

## Последствия

**Хорошее.** Локальные фильтры реагируют без сети, а ссылка сохраняет точное
состояние вида. Открытая карточка сразу пересчитывается по тем же правилам,
что и точки карты.

**Плохое.** Ответ крупнее постраничной выдачи, а широкий веер может занять
время на холодном кэше. Прогресс показывает фактическое число обращений, а
кэш делает повторные запросы быстрыми.

## Альтернативы

- Запрос на каждое изменение фильтра: точнее для нового набора данных, но
  плох для UX и для общего MCP.
- Debounce: уменьшает число запросов, но оставляет задержку в основном действии.
