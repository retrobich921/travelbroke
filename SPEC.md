# TravelBroke — техническое задание

Версия 0.1, 2026-08-19. ИИ-хакатон Туту. Живой документ: правим по ходу дня.

---

## 1. Идея в одном абзаце

Пользователь задаёт **точку отправления, дату и бюджет**. TravelBroke считает,
**куда он реально может уехать за эти деньги** — перебирая все виды транспорта
Туту и, главное, **составные маршруты с пересадками**, которые бывают дешевле
прямых. Результат — интерактивная карта России, залитая тепловой картой цен:
дёшево — лаймовый, дорого — фиолетовый. Клик по городу разворачивает конкретный
маршрут с ценой и ссылкой на покупку.

**Слоган:** «Ты на мели. Мы всё равно тебя увезём.»

**Что мы не делаем:** чат-ассистента, голосового помощника, автономный автобукинг.
Кнопку «купить» всегда жмёт человек.

## 2. Ключевая механика: почему это не просто поиск

### 2.1 Инверсия

Обычный поиск: «Москва → Сочи, сколько стоит?»
TravelBroke: «У меня 4 000 ₽ и суббота. Покажи всё, куда я попаду.»

### 2.2 Скрытая пересадка — главная фича

Прямой маршрут не всегда дешевле составного. Классика: Москва → Сочи прямым
поездом 6 800 ₽, а Москва → Ростов автобусом + Ростов → Сочи электричкой —
3 900 ₽. Ни один агрегатор такого не показывает, потому что ищет по паре
«откуда-куда», а не по графу.

**Это и есть наш вау-момент и наш ответ на вопрос «а почему нельзя просто
подключить Туту к Claude».**

### 2.3 Мультимодальность как база

Валидация по каждому виду транспорта отдельно: авиа, ж/д, автобус, электричка.
Тумблеры включают и выключают виды транспорта — карта перестраивается. Режим
«без самолёта» перестраивает всё на наземный транспорт.

## 3. Алгоритм: брутфорс → граф

### Фаза 1 — брутфорс (делаем первой, работает всегда)

```
для каждого города C из списка N (~40–60 городов):
    search_multitransport(origin, C, date, optimize_for=price)
→ прямая цена и время до каждого города
```

- Параллелизм: 8 потоков (замерено: 8 одновременных запросов, 0 ошибок, wall 13,2 с).
- Все ответы падают в дисковый кэш `tutukit.cache` — повторный прогон бесплатный.
- Прогрев кэша запускаем **первым делом**, он идёт фоном, пока пишется UI.

### Фаза 2 — граф (оптимизация и вау)

```
узлы     = города
рёбра    = рейсы между городами (цена, длительность, вид транспорта, время отпр/приб)
стоимость = цена + штраф за пересадку + штраф за время
```

- Строим граф из **уже накопленных** результатов брутфорса плюс достройка рёбер
  между городами-хабами (Москва, Питер, Казань, Ростов, Краснодар, Нижний, Самара,
  Екатеринбург, Воронеж, Тула).
- **Дейкстра** по цене → минимальная стоимость до каждого города.
- **Yen k-shortest paths** → 3 альтернативы на город: самый дешёвый, самый быстрый,
  компромисс.
- **Валидация стыковки:** пересадка засчитывается, только если между прибытием и
  отправлением остаётся минимальный буфер (по умолчанию 60 минут, для разных
  вокзалов — 120). Иначе ребро отбрасывается.
- Ограничение глубины: не более **2 пересадок** — дальше комбинаторика не окупается.

### Фаза 3 — если останется время

- Кэшируем матрицу «город × город × дата» в SQLite → мгновенный пересчёт при
  движении ползунков без единого запроса к MCP.
- Инкрементальный догон: пока пользователь смотрит карту, фоновый воркер добивает
  недостающие рёбра и карта дорисовывается сама.

## 4. Карта и визуал

### 4.1 Тепловая карта

- Основа — **OpenStreetMap**, рендер через **MapLibre GL JS** (векторные тайлы,
  плавный зум, дешёвая перерисовка при движении ползунка).
- Каждый достижимый город — точка. Цвет = цена, размер = время в пути.
- Поверх точек — интерполированная заливка (IDW по цене) как настоящий heatmap.
- Недостижимые за бюджет города — приглушённо-серые, не исчезают: важно видеть,
  что «дальше денег не хватает».

### 4.2 Палитра (под фирменный стиль Туту)

| Токен | HEX | Роль |
|---|---|---|
| `--tb-cheap` | `#d0ff1a` | самое дешёвое, лайм Туту |
| `--tb-mid` | `#8ee06a` → `#7ec8c8` → `#9fb8ff` | промежуточные ступени рампы |
| `--tb-expensive` | `#c1acff` | самое дорогое, светлый фиолет |
| `--tb-accent` | `#7b61ff` | кнопки, активные состояния |
| `--tb-ink` | `#151047` | тёмно-синий текст и фон карточек |
| `--tb-bg` | `#f3f2ff` | светлый фон интерфейса |
| `--tb-muted` | `#b9b6d6` | недостижимое, неактивное |

Рампа `#d0ff1a → #c1acff` строится **интерполяцией в OKLCH** (не в sRGB — иначе
середина уходит в грязь). Пять ступеней, легенда с подписями цен обязательна.

### 4.3 Интерфейс

- **Экран один.** Карта на весь экран, панель управления поверх неё.
- Управление: точка отправления, дата, **ползунок бюджета**, ползунок максимума
  часов в пути, четыре тумблера видов транспорта.
- Движение ползунка перекрашивает карту **мгновенно** — считаем на клиенте по
  уже загруженной матрице, без похода на сервер.
- Клик по городу → выезжающая карточка: маршрут по шагам (вид транспорта, время,
  цена каждого сегмента), итог, кнопка «Купить на Туту» (реальный deeplink).
- Прогресс-индикатор во время первичного расчёта: MCP отвечает от 0,2 до 13 с,
  «повисший» экран недопустим.

## 6. API бэкенда (черновик)

```
GET  /api/health                     → живость сервиса и MCP
POST /api/reachable                  → { origin, date, budget, max_hours, modes[] }
                                     ← [{ city, lat, lon, price, hours, transfers, mode }]
GET  /api/trip/{city_id}             → полный маршрут по шагам + deeplink на оплату
GET  /api/cities                     → справочник городов с координатами
```

`/api/reachable` возвращает **всю матрицу сразу**, чтобы ползунки работали на
клиенте без запросов к серверу.

## 7. Фичи второго уровня (добираем, если успеваем)

Порядок — по соотношению «вау к трудозатратам»:

1. **«Скрытая пересадка»** — бейдж на городах, куда составной маршрут дешевле
   прямого, с явной подписью «−2 900 ₽ через Ростов». Уже заложено в граф.
2. **«Без самолёта»** — тумблер, перестраивающий карту на наземный транспорт.
3. **Честная причина пустоты** — вместо «ничего не найдено» четыре разных
   сообщения (`tutukit.diagnose`): дата в прошлом, за горизонтом продаж, рейсов
   физически нет, фильтры слишком жёсткие.
4. **Ночной переезд вместо отеля** — где ночной поезд экономит стоимость ночи.
5. **Схема вагона** (`get_rail_seatmap` с `task=female|together|far_from_wc`) —
   самая эффектная картинка, которую отдаёт API.
6. **Поделиться маршрутом** — ссылка со всем состоянием карты в URL.
